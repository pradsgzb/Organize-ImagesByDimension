# Image Organizer by Dimension

**Organize image collections by pixel dimensions or aspect ratio, with optional small-group routing to `Others`.**

A standalone PowerShell utility for Windows. Group images into clearly named folders, add file counts to folder names, export metadata, and resume interrupted runs from saved checkpoints.

| Exact dimensions | Aspect ratios | Small groups |
| --- | --- | --- |
| `1920 x 1080` | `Ratio 16x9` | `Others` |

## Features

- **Two grouping modes:** exact width and height, or the nearest configured aspect ratio.
- **Minimum group size:** combine groups below a chosen count in one `Others` folder.
- **Optional folder counts:** use names such as `25 - 1920 x 1080`.
- **Recursive organization:** include existing subfolders and consolidate images under the input root.
- **Preview mode:** inspect proposed image moves with `-WhatIf`.
- **Filename collision handling:** generate an alternative filename by default when a destination name is already taken.
- **Recovery checkpoints:** continue an interrupted run using the same command.
- **Optional CSV report:** export dimensions, available metadata, original paths, and grouping information.
- **Efficient scanning:** read common image headers without fully decoding the image when extended metadata is not requested.

The utility moves existing files. It does not resize, crop, recompress, or deduplicate their contents.

## Requirements

- Windows with Windows PowerShell 5.1 as the target environment. The script requires PowerShell version 5.1 or later; validate other PowerShell hosts in your environment before use.
- Permission to read and move source images and create folders under the input path.
- Write access to the CSV destination when exporting a report.

The script uses .NET, `System.Drawing`, and an embedded C# image-header reader compiled through `Add-Type`. No additional PowerShell module or external image-processing application is required. Linux and macOS compatibility is not claimed.

## Quick start

1. Download [Organize-ImagesByDimension.ps1](./Organize-ImagesByDimension.ps1) and save it with that filename.
2. Open PowerShell in the folder containing the script.
3. Replace `D:\Images` below with your image folder and preview the proposed moves:

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 3 -WhatIf
```

4. Run the same command without `-WhatIf` to apply it:

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 3
```

This scans the input folder and existing subfolders. Groups with one or two images go directly into `D:\Images\Others`; groups with three or more images keep a separate dimension folder.

> **File operations:** A real run moves images and may flatten their original subfolder structure. There is no built-in undo command. Use a copy of your collection for an initial trial. Existing destination files are preserved by default; `-Force` allows their replacement.

For built-in help:

```powershell
Get-Help .\Organize-ImagesByDimension.ps1 -Full
```

## Examples

### Group by exact dimensions

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images"
```

This is the default mode. Only files directly inside `D:\Images` are scanned. A 1920 × 1080 image goes into `D:\Images\1920 x 1080`.

### Include subfolders and show group counts

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -AddCountToFolderName
```

A group containing 25 images at 1920 × 1080 uses the folder `25 - 1920 x 1080`. Counts come from the pre-move inventory for this run.

### Combine small groups and label larger groups

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 3 -AddCountToFolderName
```

| Dimensions | Images in the scan | Destination folder |
| --- | ---: | --- |
| 640 × 480 | 1 | `Others` |
| 800 × 600 | 2 | `Others` |
| 1024 × 768 | 3 | `3 - 1024 x 768` |
| 1920 × 1080 | 25 | `25 - 1920 x 1080` |

The first two groups contribute three images to the same `Others` folder. Their original filenames are kept unless a filename collision requires a new name.

### Group by aspect ratio

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -GroupByRatio
```

Images are assigned to the nearest configured ratio. For example, 1920 × 1080 and 3840 × 2160 both belong to `Ratio 16x9`.

Default ratios:

```text
1:1, 1:2, 2:1, 1:3, 3:1, 2:3, 3:2,
3:4, 4:3, 4:5, 5:4, 9:16, 16:9
```

Matching uses logarithmic ratio distance. There is no maximum-distance cutoff: an image is assigned to its nearest available ratio even when there is no exact match. Ratios are normalized, so `2:4` becomes `1:2`. Folder names use `x` because Windows does not allow `:` in a folder name.

### Choose custom ratios and a minimum count

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -GroupByRatio -Ratios "1:1","4:5","9:16","16:9" -MinFilesPerGroup 3
```

Here, the minimum count applies to the entire matched **ratio group**, including all resolutions assigned to it.

### Export image metadata

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 3 -CsvPath "D:\Reports\ImageMetadata.csv"
```

Supplying `-CsvPath` automatically enables export. Alternatively, use `-ExportCsv` to write `ImageMetadata.csv` in the current PowerShell working directory. Export also performs organization unless `-WhatIf` is specified.

### Process selected image formats

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -IncludeExtensions ".jpg",".jpeg",".png"
```

`-IncludeExtensions` replaces the default extension list for this run. Adding an extension does not add a decoder for a new format.

## The Others folder

`-MinFilesPerGroup` is the minimum number of successfully inventoried images required to retain a separate group folder.

| Setting | Behavior |
| --- | --- |
| Omitted or `0` | Disabled; use normal dimension or ratio folders. |
| `1` | Every nonempty group keeps its normal folder. |
| `3` | Groups with 1–2 images go into `Others`; groups with 3 or more keep their normal folders. |
| `10` | Groups with 1–9 images go into `Others`; groups with 10 or more keep their normal folders. |

The destination is always `<InputPath>\Others`, with images placed directly inside it. The folder name remains exactly `Others` even with `-AddCountToFolderName`, and it is created only when needed during an approved move operation.

**How counts work:** The script inventories images before moving them. It counts each original dimension or ratio group across the entire selected scan scope. Unreadable images are not included in these counts. The resulting counts stay fixed during that run and are reused when it resumes.

**Existing folders:** Add `-Recurse` to count and reorganize images already in dimension folders, `Others`, or other subfolders. Without it, those files are outside the scan scope. On a later recursive run, a group in `Others` can move to its normal folder if it now meets the threshold. Empty source folders are not removed.

## Parameters

### Input and organization

| Parameter | Default | Description |
| --- | --- | --- |
| `-InputPath <string>` | Required | Root image folder; also accepts the first positional argument. Destination folders are created under this root. |
| `-Recurse` | Off | Include subfolders present in the directory snapshot. |
| `-GroupByDimension` | Default mode | Group by exact width and height. |
| `-GroupByRatio` | Off | Group by the nearest configured ratio. Cannot be combined with `-GroupByDimension`. |
| `-Ratios <string[]>` | 13 ratios listed above | Ratio targets; available only with `-GroupByRatio`. |
| `-MinFilesPerGroup <int>` | `0` | Route groups below this count to `Others`. Range: `0`–`2147483647`. |
| `-AddCountToFolderName` | Off | Prefix normal group folder names with inventory counts. |
| `-IncludeExtensions <string[]>` | Supported extensions below | File extensions to scan; matching is case-insensitive. |
| `-Force` | Off | Replace an existing destination file with the same name. |
| `-WhatIf` | Off | Preview image moves and destination-folder creation. See the CSV caveat below. |
| `-Confirm` | Standard PowerShell behavior | Request confirmation for destination-folder creation and image moves. |

### Reporting, progress, and recovery

| Parameter | Default | Description |
| --- | --- | --- |
| `-ExportCsv` | Off | Write `ImageMetadata.csv` in the current PowerShell working directory. |
| `-CsvPath <string>` | Unset | Choose the report path and automatically enable CSV export. |
| `-LogLevel <string>` | `Info` | Console threshold: `Error`, `Warn`, `Info`, or `Debug`. |
| `-LogEachFile` | Off | Log every successful move; adds console overhead. |
| `-ProgressIntervalSeconds <int>` | `5` | Minimum interval for routine progress updates; range `1`–`3600`. Phase-completion updates can appear sooner. |
| `-CheckpointEvery <int>` | `500` | Approximate image-record interval between recovery checkpoints; range `1`–`1000000`. |
| `-DisableResume` | Off | Disable persistent recovery-state saves for this run. An unfinished prior run must be handled first. |
| `-ResetState` | Off | Discard the previous recovery plan and start a new one using the current options. |

## Supported formats

| Format | Default extensions |
| --- | --- |
| JPEG | `.jpg`, `.jpeg`, `.jpe`, `.jfif` |
| PNG | `.png` |
| BMP | `.bmp` |
| GIF | `.gif` |
| TIFF | `.tif`, `.tiff` |
| WebP | `.webp` |

The header reader supports common variants of these formats. The fast TIFF reader supports classic TIFF and reads dimensions from its first image directory; BigTIFF is not supported by that reader. GIF and WebP are organized as whole files, without extracting animation frames.

Grouping does not apply an EXIF orientation transform. Pixel dimensions may therefore differ from the orientation shown by an image viewer that automatically rotates photographs. Files with unsupported extensions are skipped; image-read failures are logged.

## CSV report

The report is an inventory of images successfully read before the move phase. It is UTF-8 with a byte-order mark and contains these columns:

| Column | Meaning |
| --- | --- |
| `FileName` | Original filename, including extension. |
| `OriginalFullPath` | Source path recorded during inventory. |
| `WidthPixels` | Image width in pixels. |
| `HeightPixels` | Image height in pixels. |
| `HorizontalPPI` | Horizontal resolution reported by the image reader, when available. |
| `VerticalPPI` | Vertical resolution reported by the image reader, when available. |
| `XPComment` | Windows XPComment metadata, when available. |
| `LastModifiedDateTime` | Source file's last-write timestamp. |
| `CreationDateTime` | Source file's creation timestamp. |
| `GroupingMode` | `Dimension` or `Ratio`. |
| `Group` | Original dimension or matched ratio group. |

`Group` remains the original group key even when an image is routed to `Others`. The CSV does not include final destination paths, collision-renamed filenames, or per-file move results.

Export attempts extended metadata through `System.Drawing`. If that fails, it falls back to the fast dimension reader; optional metadata fields remain blank when unavailable. PPI values describe reported image resolution, not verified physical print size.

> **CSV and preview behavior:** `-WhatIf` prevents image moves and destination-folder creation, but an explicitly requested CSV is still written and can overwrite an existing report at the same path. Temporary inventory files may also be created. `-Confirm` does not protect CSV writes.

## Recovery

Persistent recovery is enabled by default. If execution is interrupted, rerun the **same command against the same input folder** to continue from the saved checkpoint.

- A normal run without counts, small-group routing, or CSV uses direct organization and checkpoints at directory boundaries.
- Enabling any of those options uses an on-disk inventory manifest. Inventory checkpoints occur at directory boundaries; the move phase checkpoints its manifest position.
- Work after the last checkpoint may be revisited. Recovery checks source and expected destination paths; it does not verify file contents by checksum.
- Changes to grouping, scan scope, export configuration, or an enabled minimum count can invalidate the previous plan. The script rejects incompatible recovery settings.

Keep the collection stable during a run and while recovering it. Preserve the organizer's recovery files in the input folder until the run finishes. A per-root lock prevents two instances of this utility from organizing the same input folder simultaneously.

### Intentionally start a new plan

After confirming no organizer instance is still running:

```powershell
.\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 5 -ResetState
```

`-ResetState` discards the saved plan; it does not undo previous moves. `-Recurse` includes files already moved into subfolders when rebuilding the inventory.

Recovery files are normally removed when processing reaches completion, including completion with individual file errors. A later run is then a new scan rather than a retry queue for those errors. A fatal interruption preserves state when recovery is enabled and state saving succeeds.

## Performance and results

The script streams file enumeration and keeps a directory snapshot so newly created destination folders are not added to the scan midway through a run. Recursive scanning skips directory reparse points and junctions.

The basic mode avoids a full image inventory. Folder counts, `-MinFilesPerGroup`, and CSV export require an initial inventory pass and temporary disk space. CSV export adds metadata-reading work; `-LogEachFile` adds console output. Checkpoint intervals trade throughput against the amount of work repeated after interruption, and directory-based phases may exceed the configured record interval within a large directory.

Runtime depends on storage, file count, formats, and selected options. No fixed throughput or completion-time guarantee is provided.

At completion, the script writes a summary object that can be captured in PowerShell:

```powershell
$result = .\Organize-ImagesByDimension.ps1 -InputPath "D:\Images" -Recurse -MinFilesPerGroup 3
$result | Select-Object Status, FilesMoved, FilesFailed, InventoryFailed, Elapsed
```

| Status | Meaning |
| --- | --- |
| `Completed` | Processing finished without recorded move or inventory failures. |
| `CompletedWithErrors` | Processing finished, but one or more move or inventory failures were recorded. Review the error output. |
| `WhatIfCompleted` | Preview finished without recorded move or inventory failures. |

A fatal error throws an exception instead of returning the normal summary. For automation, inspect the summary and handle exceptions; do not use process exit status alone as proof that every file was organized. Directory-discovery warnings should also be reviewed because they can indicate subfolders were not scanned.

## Troubleshooting

| Issue | What to check |
| --- | --- |
| PowerShell cannot find the script | Open PowerShell in the script's folder, use the exact filename, and include the `.\` prefix. |
| Script execution is blocked | Review the script and follow your machine's execution policy. Inspect `Get-ExecutionPolicy -List`; a downloaded-file block and an execution-policy restriction are different issues. |
| Existing folders are not reorganized | Include `-Recurse`. Without it, only files directly under `-InputPath` are scanned. |
| No images are moved | Check the input path, extensions, whether `-WhatIf` is active, and whether images are already at their calculated destination. |
| `Others` was not created | Confirm a scanned, readable group is strictly below the threshold. A group equal to the threshold keeps its normal folder. |
| An unfinished run has different options | Resume with the original options, or intentionally start a new plan with `-ResetState`. |
| The organizer lock cannot be obtained | Check for another running instance and verify access to the input folder. A leftover lock filename alone does not prove a process is running. |
| Metadata cannot be read | Check whether the image is corrupt, inaccessible, or a format variant the available readers cannot handle. |
| CSV PPI or comments are blank | These fields are optional; the image or reader may not provide them. |
| A filename gained a suffix | The destination name already existed. The utility uses a source-path hash suffix, with a numeric suffix if needed, to avoid overwriting by default. |
| Some source folders are empty afterward | Empty-folder removal is outside the utility's current behavior. |

## Contributing

Issues and improvements are welcome. When reporting a problem, include the PowerShell version, command used, relevant error text, image format, and a minimal reproducible example. Use synthetic images and remove private paths or metadata from shared logs and reports.

Before proposing a change, check its effect on grouping, filename collisions, preview behavior, CSV export, and interrupted-run recovery. For minimum-count changes, verify groups below, exactly at, and above the threshold.
